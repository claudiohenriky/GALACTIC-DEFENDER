# Índice de documentação

Este índice reúne os documentos de processo usados para organizar mudanças, revisar a interface e registrar validações do projeto.

## Ordem recomendada de leitura

1. [Fluxo de desenvolvimento](DEVELOPMENT_WORKFLOW.md) — explica o ciclo de trabalho, a separação entre versões de trabalho e a versão oficial, e os cuidados antes de integrar alterações.
2. [Checklist de revisão de alterações](CHANGE_REVIEW_CHECKLIST.md) — orienta a revisão de escopo, qualidade, consistência e rastreabilidade antes de aceitar uma mudança.
3. [Checklist de acessibilidade](ACCESSIBILITY_CHECKLIST.md) — ajuda a verificar legibilidade, navegação, feedback visual e uso por diferentes pessoas.
4. [Modelo de registro de validação](VALIDATION_RECORD_TEMPLATE.md) — fornece um formato padronizado para documentar ambiente, verificações, evidências, problemas e decisão da rodada.

## Como usar os documentos

- Consulte o fluxo de desenvolvimento antes de iniciar uma tarefa.
- Durante a implementação, mantenha a alteração limitada ao escopo aprovado.
- Antes de concluir, percorra os checklists aplicáveis e registre o resultado.
- Não marque uma etapa como validada sem evidência verificável.
- Registre limitações, falhas e itens pendentes; não os apresente como concluídos.

## Critério de conclusão

Uma alteração só deve ser considerada concluída quando:

- o objetivo e o escopo estiverem documentados;
- a revisão aplicável tiver sido realizada;
- as verificações executadas e seus resultados estiverem registrados;
- as limitações conhecidas e os próximos passos estiverem explícitos;
- a branch oficial não tiver sido modificada sem autorização.

## Estado da documentação

Os arquivos listados acima são instrumentos de organização e controle de qualidade. A existência desses documentos não significa que a aplicação tenha sido executada, que testes manuais tenham sido concluídos ou que uma versão esteja aprovada para publicação. Essas afirmações exigem evidências próprias, registradas no modelo de validação.
